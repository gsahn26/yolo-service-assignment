# 선택 과제 A — YOLO 서비스 (객체 탐지 + 이미지 분할)

사진을 넣으면 **탐지(박스·클래스·점수)** 와 **분할(마스크)** 결과를 보여 주고, 신뢰도 임계값 **0.25 / 0.50** 결과를 비교하는 작은 서비스입니다.

- **결과 확인 페이지:** https://gsahn26.github.io/yolo-service-assignment/
- **실행 노트북:** [`yolo_service.ipynb`](yolo_service.ipynb) (실행 결과가 저장된 상태)
- **실행 코드:** [`yolo_service.py`](yolo_service.py)

---

## 1. 실행 위치

| 항목 | 내용 |
|---|---|
| 어디서 | **Claude(Cowork) 클라우드 샌드박스** — 코딩 에이전트(Claude)에게 요청해 리눅스 컨테이너에서 실행 |
| 하드웨어 | x86_64, **GPU 없음 → CPU** (`device=cpu`) |
| 버전 | Python 3.13 · ultralytics 8.4.208 · torch 2.15 · OpenCV 5.0 (자세한 값은 [`manifest.json`](manifest.json)) |
| 실행 일시 | 2026-11-10 (manifest의 `created_at`) |

## 2. 실행 방법 (다시 실행하기)

내 컴퓨터(로컬)나 Colab 어디서든 같은 순서로 실행됩니다.

```bash
git clone https://github.com/gsahn26/yolo-service-assignment.git
cd yolo-service-assignment
pip install -r requirements.txt     # ultralytics 설치
python yolo_service.py              # input/ 의 모든 사진 처리
```

- 모델 가중치(`yolo26n.pt`, `yolo26n-seg.pt`)는 첫 실행 때 Ultralytics 공식 릴리스에서 **자동으로 내려받습니다** (그래서 저장소에는 넣지 않았습니다).
- 다른 사진을 넣으려면 `input/` 폴더에 jpg/png를 넣고 다시 실행합니다. 특정 파일만: `python yolo_service.py 내사진.jpg`
- 노트북으로 보려면 `yolo_service.ipynb`를 열고 위에서부터 실행합니다.

**저장되는 결과** — `outputs/yolo/<사진이름>/`

| 파일 | 내용 |
|---|---|
| `detect_conf0.25.jpg`, `detect_conf0.50.jpg` | 원본 위에 박스를 그린 결과 이미지 |
| `segment_conf0.25.jpg`, `segment_conf0.50.jpg` | 원본 위에 마스크를 겹친 결과 이미지 |
| `*_conf*.json` | 객체별 클래스·점수·박스 좌표(픽셀 / 0~1 정규화), 분할은 마스크 면적까지 |
| `segment_conf*_masks/*.png` | 객체별 마스크 (원본 크기, 흰색 = 대상) |
| `summary.json` | 임계값별 개수와 0.25→0.50 사이에서 사라진 후보 목록 |
| `*_conf0.10.*` | 참고용: 0.25 아래에 어떤 후보가 있었는지 보기 위한 결과 |

## 3. 도구·설정을 고른 이유

| 선택 | 이유 (작업 목적과 연결) |
|---|---|
| **Ultralytics YOLO** | 한 패키지로 탐지와 분할을 둘 다 실행할 수 있고, 결과에서 박스 좌표·점수·마스크를 바로 꺼낼 수 있어 “어디를 찾았는가”를 보여 주는 목적에 맞음 |
| **`yolo26n.pt` / `yolo26n-seg.pt`** (n = nano) | 과제 지정 모델. 가장 작은 크기라 GPU 없는 CPU 환경에서도 사진 1장을 몇 초 안에 처리 |
| **`imgsz=640`** | 모델이 학습된 기본 입력 크기. 결과 좌표는 원본(810×1080) 기준으로 되돌려 저장 |
| **`device=cpu`** | 실행 환경에 GPU가 없음. 누구나 같은 조건으로 다시 실행 가능 |
| **`conf=0.25 / 0.50`** | 과제 지정. 낮은 기준(후보 많이 보기)과 높은 기준(확실한 것만)을 비교 |
| **참고용 `conf=0.10`** | 0.25와 0.50 결과가 같게 나와서, “기준 아래에 숨은 후보가 정말 없는지” JSON 점수로 확인하려고 추가 |
| **JSON + 마스크 PNG 저장** | 그림만 보면 확인이 끝나지 않음. 좌표와 마스크를 파일로 남겨야 다른 프로그램에서 읽고, 원본 위치로 되돌아가 대조할 수 있음 |

## 4. 결과 요약 (`input/bus.jpg`, 810×1080)

| 실행 | conf 0.10 (참고) | conf 0.25 | conf 0.50 |
|---|---|---|---|
| 탐지 | bus 1, person 4, **stop sign 1 (0.13)** | bus 1, person 4 | bus 1, person 4 |
| 분할 | bus 1, person 4 | bus 1, person 4 | bus 1, person 4 |

**0.25 → 0.50 으로 올려도 사라진 박스가 없습니다.** JSON을 보면 남은 결과의 점수가 모두 0.65 이상이고, 0.25~0.50 사이에 걸친 후보가 하나도 없었기 때문입니다 (`summary.json`의 `dropped_between_0.25_and_0.50: []`). 0.25 아래 후보 중 가장 높은 것은 왼쪽 끝 표지판의 `stop sign 0.13`이었습니다.

**박스 안에 배경이 얼마나 섞였나** (분할, conf 0.25)

| 대상 | 점수 | 마스크 면적 | 박스 면적 | 마스크/박스 |
|---|---|---|---|---|
| 사람 (베이지 코트, 왼쪽) | 0.88 | 49,046 px | 97,053 px | 50% |
| 사람 (오른쪽 끝, 검은 옷) | 0.86 | 21,190 px | 68,112 px | 31% |
| 버스 | 0.86 | 255,100 px | 410,281 px | 62% |
| 사람 (검은 재킷, 가운데) | 0.81 | 33,160 px | 56,023 px | 59% |
| 사람 (왼쪽 끝, 일부만 보임) | 0.65 | 10,681 px | 23,684 px | 45% |

→ 박스 면적의 30~60%만 실제 대상입니다. 면적이 필요한 질문에는 박스가 아니라 마스크를 써야 하는 이유입니다.

## 6. 처리 범위와 한계 (정직하게 적기)

- **처리한 사진은 `bus.jpg` 1장뿐입니다.** 과제 안내의 “공개해도 되는 자기 사진”은 아직 넣지 않았습니다. `input/`에 넣고 다시 실행하면 같은 형식으로 결과가 추가됩니다.
- **정답 라벨이 없어** 정밀도·재현율·mAP 같은 수치는 계산하지 않았습니다. 위 판정은 원본을 눈으로 확대해 본 결과입니다.
- 1차 대조는 코딩 에이전트(Claude)와 함께 했고, 표의 ‘확인 필요’ 칸은 사람이 다시 확인해야 하는 곳입니다. 추측으로 채우지 않았습니다.
- 점수(confidence)는 후보를 추리는 값이며, “0.88 = 88% 확률로 맞음”이라는 뜻이 아닙니다.
